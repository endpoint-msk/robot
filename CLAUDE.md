# CLAUDE.md

Гайд для LLM по проекту `endpoint-robot` — телеграм-бота хакерспейса на TypeScript + [mtcute](https://mtcute.dev).

## Документация mtcute

Полный индекс гайда и API-референса в формате для LLM лежит здесь: <https://mtcute.dev/llms.txt>. Это «table of contents» с прямыми ссылками на `.md`-страницы; используй его как первый источник, когда нужны сигнатуры/имена методов или примеры (handlers, filters, banChatMember, deleteMessages и т. п.). Полный API-референс: <https://ref.mtcute.dev>.

## Что делает бот

Пять независимых подсистем, разделяющих общий стейт:

1. **Сборы донатов** (`src/fundraiser.ts`, `src/handlers.ts`, `src/scheduler.ts`) — один сбор на календарный месяц (UTC), команды `/goals`, `/donate`, `/remove`, `/setgoal`, `/settitle`. Лидерборд группируется по нику (lower-case) и сортируется по убыванию суммы; топ-3 — медали 🥇🥈🥉. Пагинация по `PAGE_SIZE = 10`. Цель, тема и описание — «липкие»: новый период создаётся с настройками прошлого (`ensureCurrentFundraiser`), сбрасываются только донаты. Прошлые сборы — `/history` (доступна всем участникам, как `/goals`): список периодов с итогами + кнопки на каждый (`pastFundraisers`/`renderHistoryList`, пустые периоды и текущий отсекаются, показываем последние `HISTORY_LIMIT = 12`), по кнопке — полный лидерборд с пагинацией; `/history 2026-06` открывает период сразу. Сообщение истории **не** попадает в `lastMessages` — иначе шедулер смены периода перерисовал бы его в текущий сбор.
2. **Присутствие резидентов** (`src/presence.ts`) — резиденты = админы любого из allowlist-чатов. `/start` в личке открывает меню «Отметиться с/без ника». Каждые 3 ч (`PRESENCE_PING_INTERVAL_MS`) — пинг в личку; если 15 минут (`PRESENCE_PING_TIMEOUT_MS`) нет нажатия «Я внутри» — отметка снимается. Постоянной авто-поверхности «кто внутри» отдельным сообщением больше нет: присутствие показывается **на доске** «кто сегодня в спейсе» (`src/hosting-board.ts`, блок «Сейчас в спейсе» на доске сегодняшнего дня), а чек-ин/чек-аут/MAC дёргают `setPresenceChangeHook` → `syncHostingBoard`. Команда `/inside` доступна **любому участнику** allowlist-чата и постит разовый снимок списка (`postPresenceList`, без пина/редактирования). **Авто-отметки по MAC** (`src/keenetic.ts`): `/bindmac <MAC>` в личке привязывает MAC; поллер опрашивает RCI-API Keenetic и сам ставит отметку (`source: 'mac'`), пока устройство онлайн, снимает после `MAC_ABSENCE_GRACE_MS` (10 мин) отсутствия. MAC-отметки **не пингуются** (пинг/таймаут только для `source: 'manual'`).
3. **3D-принтер** (`src/printer.ts`) — команда `/printer` тянет статус из Moonraker (Klipper) по `PRINTER_URL`. Доступна в личке всем и в allowlist-чатах. При активной печати показывает прогресс + картинку (превью gcode / снимок вебки, переключаются кнопками) и кнопку «Уведомить по окончании». Поллер (тик 30 с) ловит переход в терминальное состояние и шлёт подписчикам в личку.
4. **Хостинг гостей** (`src/hosting.ts`, `src/webapp.ts`, `webapp/`) — Telegram Mini App: гость оставляет заявку на визит (день из ближайших 7 + время + цель; перед самой первой заявкой — согласие с правилами спейса, см. поток ниже), резидент видит обзор недели и жмёт «Захостить». Включается `WEBAPP_URL` (бот поднимает HTTP-сервер `WEBAPP_HOST:WEBAPP_PORT`, статика `webapp/dist` + JSON API). Резиденты по умолчанию получают в личку уведомления о новых заявках в режиме «только на сегодня» (`hostingNotify`, дефолт см. `DEFAULT_HOSTING_NOTIFY`); настраивается в миниаппе («все» / «только сегодня» / выкл). Там же настройки MAC-привязок — общий стейт с `/bindmac`/`/unbindmac`/`/settings`. Кнопки входа: menu button рядом с полем ввода (ставится API-вызовом на старте), URL-кнопка под списком `/inside` (deep link `t.me/<bot>?startapp=hosting`, требует включённый Main Mini App в BotFather) и webView-кнопки в личке (`/start`, `/inside`). Подтверждённый визит можно добавить в календарь: `.ics` отдаётся по `GET /visit.ics` (см. поток ниже). Резидент может **попросить перенести** визит (день и/или время) — пинг-понг предложений с гостем — и **заблокировать** гостя (бан во всех чатах + отказ в миниаппе, см. поток ниже); эти действия и **заметка о госте** (общая память резидентов, см. поток ниже) — свайпом влево по строке заявки. Тема — системная по умолчанию, выбор в настройках; настройки открыты всем, но гостю в них доступна только тема. `DEV_USER_IDS` — дев-меню миниаппа: переключатель перспективы «резидент ↔ гость», создание фейковых заявок (`dev.seed`), правка/удаление любых заявок (`dev.update`/`dev.delete`) и список заблокированных с разблокировкой (`unblock`).
5. **Анонсы версий** (`src/announce.ts`) — рассылка объявлений во все allowlist-чаты. Релизы делает воркфлоу `.github/workflows/release.yml` (пуш тега `vX.Y.Z` на main → ченджлог из `git log` между прошлым и текущим тегом, ВСЕ коммиты, а не только PR → GitHub Release; версия = тег, `package.json` не бампается). Дев (`DEV_USER_IDS`) из дев-меню миниаппа тянет описание последнего релиза (`GET api.github.com/.../releases/latest`, репо публичное — токен не нужен, `GITHUB_REPO`), правит текст, видит превью и жмёт «Разослать» — уходит `broadcastAnnouncement` во все чаты, кроме замьюченных (`/announcemute`, только админ чата). Ядро — не «анонс версии», а бродкаст произвольного текста: версия лишь префилит textarea. `lastAnnouncedVersion` в стейте — маркер «до какой версии уже анонсили».

```
src/handlers.ts     — команды сборов + общий callback для пагинации/обновления, проверки allowlist/админа
src/presence.ts     — /start, callback presence:*, трекер активности чатов, watcher удалений, шедулер пингов/тишины
src/printer.ts      — /printer, callback printer:* (превью/камера/подписка), запросы к Moonraker, поллер окончания печати

src/residents.ts    — ResidentDirectory: единый источник «кто резидент/админ» (isResident/presenceChats/isChatAdmin); реализация createTelegramResidentDirectory — поверх getChatMember. Точка замены под Authentik
src/fundraiser.ts   — чистая модель: createFundraiser, buildLeaderboard, renderFundraiser, parseDonateArgs, parseRemoveArgs

src/hosting-board.ts— доска «кто сегодня в спейсе»: закреплённое сообщение в чат про ближайший активный день + кнопка «Хочу прийти», syncHostingBoard + шедулер
src/webapp.ts       — HTTP-сервер миниаппа: статика webapp/dist (сборка Vite) + POST /api/* c проверкой подписи initData + GET /visit.ics (initData в query)
webapp/             — фронт миниаппа: React + Vite + TypeScript (исходники в webapp/src, сборка в webapp/dist). main.tsx → Root → App; экраны в src/screens/, переиспользуемые компоненты в src/components/, внешний стор + стек экранов в src/store.ts. Дизайн — iOS, светлая и тёмная темы (src/app.css — глобальный CSS, 1:1 со старым макетом)
src/scheduler.ts    — раз в минуту перерисовывает «последнее сообщение со сбором» при смене UTC-месяца
src/announce.ts     — анонсы: fetchLatestRelease (GitHub API), buildDefaultAnnouncement (тело релиза → текст), broadcastAnnouncement (во все чаты минус /announcemute)
src/backup.ts       — дев-бэкапы стейта: /backup (разово) и /autobackup <интервал> (расписание в state.backups + шедулер, тик 60 с)
src/storage.ts      — JSON-файл с атомарной записью через writeChain (промис-цепочка), tmp+rename; snapshot()/path() отдают стейт и путь для бэкапов

```

### Ключевые инварианты

- **`onCallbackQuery`: на «чужой» callback всегда `return PropagationAction.Continue`, а не голый `return`.** Голый `return` (или `return undefined`) останавливает пропагацию, и другие `onCallbackQuery`-хендлеры (presence, printer, fundraiser) НЕ увидят свой callback. Симптом — «кнопка ничего не делает». Все callback-хендлеры зарегистрированы независимо в разных модулях.
- **`State` плоский и однофайловый**, всё через `Storage.update(mutator)` — мутация in-memory + запись на диск. Не читать `state` из нескольких мест без понимания, что `update` сериализует записи; чтение через `storage.get()` возвращает живую ссылку.
- **`periodKey` = `YYYY-MM` по UTC**. Сменa месяца → `scheduler.ts` перерисовывает `lastMessages[chatId]` под новый сбор. Никогда не сравнивать ключи через локальное время.
- **Allowlist `ALLOWED_CHATS`** — единственный гейт «бот тут вообще работает». В чужих чатах бот **молчит** (никаких ответов даже на ошибки) — это сознательный design: см. `requireUserInAllowedChat`/`requireChatAdminInAllowedChat`.
- **Кто резидент/админ — только через `ResidentDirectory`** (`src/residents.ts`), а не через прямой `getChatMember` в хендлерах. Четыре вопроса: `isResident` (юзер вообще резидент), `presenceChats` (в каких чатах показывать его присутствие), `isChatAdmin` (вправе ли выполнять админ-команду в этом чате), `access` (резидент+забанен одним ответом — оба факта берутся из одного обхода allowlist-чатов, раздельные вызовы удвоили бы round-trip'ы на каждый запрос миниаппа). Сейчас всё это — живой `getChatMember` (кэша нет, актуальность ценой API-вызова); при переходе на Authentik меняется только реализация в `residents.ts`. NB: `presenceChats` сейчас == «где ты админ», но с Authentik совпадёт не обязательно — Authentik не знает про Telegram-чаты.
- **`/inside` — для всех участников allowlist-чата**, остальные команды сборов — только для админов. Это закреплено двумя разными хелперами и двумя scope-ами в `setMyCommands`.

### Поток сообщения сбора

`/goals` или `/donate` → `ensureCurrentFundraiser` → `renderFundraiser` → `msg.answerText` + `rememberLastMessage`. Дальше любые `/donate`, `/setgoal`, `/settitle`, `/remove`, кнопки «Обновить»/`◀️▶️` → `refreshLastMessageInChat`, который **редактирует** запомненное сообщение. Если оно удалено/протухло (`MESSAGE_ID_INVALID`, `MESSAGE_DELETE`) — забываем id, при следующем `/goals` запомнится новое.

### Поток presence

- Чек-ин: callback `presence:checkin:nick|anon` → `checkInResident` пишет в `state.presence[userId]` и дёргает `onPresenceChanged` (хук `syncHostingBoard`) — доска показывает актуальное «Сейчас в спейсе».
- Чек-аут: `presence:checkout` → `removePresence` (тоже дёргает хук доски).
- Шедулер `startPresenceScheduler` (тик 60 с): только пинги/таймауты по `source: 'manual'`. Отдельного авто-постинга списка присутствия больше нет — поверхность «кто внутри» это доска (`hosting-board.ts`); presence зовёт её через хук. Без миниаппа хук не ставится: авто-доски нет, остаётся только ручной `/inside` (`postPresenceList`).

### Поток printer

- `/printer` → `fetchPrinterStatus` (Moonraker `/printer/objects/query`). Не печатает → просто текст. Печатает → `fetchPrinterThumbnail` (превью из метаданных gcode) + `activeKeyboard('preview')`.
- Кнопки `printer:view:preview|camera` → `ctx.editMessage({ media })` подменяет картинку (превью gcode ↔ `fetchWebcamSnapshot`); у активного вида галочка ✅, повторный тап ловит `MESSAGE_NOT_MODIFIED`.
- Кнопка `printer:notify` → перепроверяет live-статус, пишет userId в `state.printerSubscribers` и шлёт подтверждение в личку с кнопкой `printer:unsubscribe`. Если бот не может писать в личку — просит нажать `/start`.
- `startPrinterCompletionWatcher` (тик 30 с): при переходе из активной печати в `complete`/`cancelled`/`error` шлёт подписчикам в личку и **чистит весь список** (подписка одноразовая, на текущую печать — иначе «переедет» на следующую).
- **Превью зависит от слайсера**: миниатюры должны быть встроены в gcode. **Снимок вебки** — `snapshot_url` первой камеры из `/server/webcams/list`, фолбэк `/webcam/?action=snapshot`.

### Поток хостинга

- Аутентификация API — только подпись `initData` миниаппа (`validateInitData` в `webapp.ts`, HMAC c ключом `WebAppData` + TTL 24 ч). Никаких сессий/куки. `isResident` = админ хотя бы одного allowlist-чата, проверяется на каждый запрос — вместе с баном, одним вызовом `residents.access`.
- `POST /api/bootstrap` — общий снапшот: 7 дней от «сегодня» (пояс спейса), свои заявки, настройки. **Гостям в днях отдаются только счётчики** (total/approved), детали заявок — резидентам и dev-аккаунтам (последним они нужны для дев-меню). Все мутирующие методы возвращают свежий bootstrap, фронт просто заменяет стор.
- Ключ дня — `YYYY-MM-DD` по поясу спейса (`HOSTING_TZ_OFFSET_MINUTES`, дефолт 180 = МСК, без DST). Никогда не считать «сегодня» через локальное время процесса — только `todayKey(offset)`. Время слота «на сегодня» не должно быть в прошлом: `isPastSlot`/`nowTimeKey` сравнивают с текущим временем в поясе спейса (bootstrap отдаёт `nowTime`, фронт ставит `min` у `<input type=time>` и гейтит перед отправкой).
- Правила заявок: день в окне `[сегодня; +6]`, одна активная заявка гостя на день, отмена заявки = удаление из стейта. «Захостить» может любой резидент (первый успевший), отменить одобрение — только сам одобривший (заявка возвращается в pending, гостю уходит DM).
- **Правка заявки гостем** (`editHostingRequest`, API `edit`): гость меняет день/время/цель/анонимность своей заявки, только пока она `pending` (иначе `not_pending`); те же гейты дня/времени/дубля, что при создании; незакрытое предложение переноса при этом снимается — автору-резиденту уходит DM (`notifyProposalDroppedByEdit`), а если гость правкой выставил ровно предложенный слот, это считается согласием и шлётся `notifyProposalAccepted`. Снимок предложения берётся ДО вызова `editHostingRequest`: `request` — живая ссылка на объект стейта, после правки `proposal` уже null. У одобренной заявки правка запрещена (гость отменяет и создаёт заново).
- **Кто придёт** (`attendeesView`, поле `days[].attendees` — видно всем, включая гостей): подтверждённые (`approved`) гости **без анонимных** + резиденты, отметившиеся «я приду». Резиденты идут первыми (приоритет) и с пометкой `resident:true`; дубли по `userId` схлопываются в пользу резидентской строки (один человек мог и отметиться, и завести заявку). Цель визита в публичный список НЕ попадает. Гость включает анонимность (`request.anon`) при создании/правке — резиденты в своих списках (`requests`) видят его всегда, с меткой «инкогнито».
- **Отметка резидента «я приду»** (`setResidentAttendance`/`residentsAttendingDay`, стейт `hostingAttendance`, ключ `${dateKey}#${userId}`, API `attend`): без заявки, просто присутствие в списке дня; кнопка-переключатель на экране дня резидента; день — в окне `[сегодня; +6]`.
- **Перенос дня/времени** (`proposeReschedule`/`acceptReschedule`/`clearReschedule`): пинг-понг вокруг `request.proposal` (`RescheduleProposal = { dateKey, time, by: 'resident'|'guest', user, at }` или null). Предложение несёт **полный слот** — резидент может попросить перенести и день, и время одним предложением (API `propose` берёт `dateKey` + `time`; гость по умолчанию шлёт свой текущий `dateKey`, двигая только время). Сторона-адресат принимает (`proposal.accept` — согласованными становятся `request.dateKey`/`request.time`, предложение снимается) либо снимает (`proposal.decline` — слот не меняется). «Захостить» гасит висящее предложение.
  - Предложенный день проверяется как при создании: окно `[сегодня; +6]`, не в прошлом, без дубля (у гостя нет другой заявки на этот день). На `accept` день **перепроверяется** (`acceptReschedule` берёт `tzOffset`): выпал из окна или появился дубль → предложение снимается, ответ `stale`, фронт ресинкается.
  - Встречное `propose` **тем же слотом** (`dateKey`+`time`), что висит в предложении другой стороны, трактуется как `proposal.accept` — иначе стороны бесконечно пингуют друг друга одинаковым слотом.
  - `propose` слотом, **равным уже согласованному** `request.dateKey`/`request.time`, — no-op: стейт не меняется, DM не уходит. Проверка идёт **после** встречного согласия. Фронт гасит это ещё до запроса (`Visit.tsx`, `proposeRescheduleFor`).
  - `propose` слотом, что **уже висит в твоём же предложении** (`counter.by === by && counter.dateKey === dateKey && counter.time === time`), — тоже no-op.
  - **pending**: резидент предлагает слот на любой заявке, гость отвечает своим **только в ответ** на предложение резидента.
  - **approved**: перенос доступен обеим сторонам по своей инициативе — подтверждённый визит тоже иногда надо сдвинуть, в т.ч. на другой день. Меняются `dateKey`/`time`, статус и `approvedBy` остаются. Со стороны резидентов работать с таким предложением вправе **только хост** (`approvedBy`), иначе чужой визит подвинет посторонний. (Прямая правка заявки гостем так и осталась `pending`-only — одобренную гость двигает только через перенос.)
  - Уведомления адресные: резидент→гость по `guest.userId`; гость→ хосту (`approvedBy.userId`), а на pending — резиденту из прошлого предложения. Если адреса нет (встречное предложение гостя без предыдущего), DM не шлём. Текст показывает день, если он меняется, иначе только время, и **называет автора действия** (`actor` в `notifyProposalAccepted`/`notifyProposalCancelled`) — иначе получателю не видно, кто принял/снял. У снятия две формулировки: «снимает предложение» (сняла сторона автора, `withdrawn`) и «отклоняет перенос» (отказал адресат); действие одно (`proposal.decline`), но смысл для получателя разный.
- **«Позвать в спейс»** (`src/hosting-invite.ts`, API `invite.list`/`invite`, экран `Invite` в миниаппе): резидент с экрана дня зовёт человека на этот день. Кандидаты — резиденты (`listResidents`, живой `getChatMembers`) + гости из заявок (`listKnownGuests`, включая архивные; без заблокированных и фейков дев-сида), себя в списке нет; у тех, кто уже придёт (отметка «я приду» или заявка на день), кнопка заменена меткой. Зов — DM: резиденту inline-кнопка «Приду» (callback `hostinvite:come:<dateKey>` → `setResidentAttendance` + пересборка доски, потом кнопка гасится пустой inline-разметкой), гостю — вход в миниапп (у него визит это заявка со временем и одобрением). Стейт зовы не пишут, лимитов нет — функция только для резидентов. Закрытая личка видна только по ошибке отправки → `409 dm_closed`.
- **Профиль открывается только по @нику** (`openProfile` в `webapp/src/telegram.ts`): у человека без ника ссылки `t.me` не существует, строка просто не тапается. Обходные пути проверены и отброшены: `tg://user?id=` из вебвью не открывается **ни в каком виде** (`openTelegramLink` берёт только `t.me`, `openLink`/`window.open`/`location.href` схему молча проглатывают), а карточка от бота с text-mention бесполезна для тех, у кого в приватности запрещена ссылка на аккаунт — Telegram выкидывает сущность упоминания, остаётся голый текст. Не возвращать без нового механизма со стороны Telegram.
- **Правила спейса перед первой заявкой** (`HOSTING_RULES_VERSION`/`hasAcceptedRules`/`acceptRules`, стейт `hostingRules`, ключ — userId, API `rules.accept`, экран `Rules`): гость один раз читает правила сообщества, отмечает галочку и жмёт «Согласиться и продолжить». Вход в форму заявки идёт через `startNewRequest()` (`store.ts`): нет согласия — открывается экран правил, есть — сразу форма. **Гейт продублирован на сервере**: `create` без согласия отвечает `403 rules_required` — навигацию миниаппа можно обойти. Текст правил живёт во фронте (`screens/Rules.tsx`), в стейт пишется только версия: правишь текст — поднимаешь `HOSTING_RULES_VERSION`, и согласие спрашивается заново у всех. Дев-сид (`dev.seed`) гейт не проходит — он создаёт заявки от фейковых гостей напрямую.
- **Заметка о госте** (`setGuestNote`/`guestNoteFor`/`listGuestNotes`, стейт `guestNotes`, ключ — userId гостя, API `note.set`, экран `GuestNote`): **одна заметка на человека и общая для резидентов** — правит любой, `by` перезаписывается автором последней правки. Гостю заметки не уходят вовсе (`bootstrap.notes` только резидентам), в том числе о нём самом. Вход — свайп влево по строке заявки («Заметка», доступна и в архиве: заметка живёт отдельно от заявки) и тап по иконке-флажку рядом с именем; **иконка — единственный след заметки в списке**, текст в строку не выводится. Пустой текст = удалить заметку (сервер трактует так же). Блокировка гостя заметку **не** стирает — она объясняет, почему он в блоке. Заметки отдаются разом все: их единицы, а строка заявки с флажком встречается и в архиве, который грузится отдельным запросом.
- **Блокировка участника** (`blockUser`/`unblockUser`/`isBlocked`, стейт `blockedUsers`, ключ — userId): **любой резидент** блокирует гостя свайпом влево по строке его заявки (API `block`, гейт `requireResident`, берёт `id` заявки → `guest`). Бот банит участника во **всех** `ALLOWED_CHATS` (`banChatMember`), стирает все его заявки/отметки/присутствие и закрывает ему миниапп — `403 blocked` на любой `/api/*` и `/visit.ics`. **Источников бана два**: своя запись в `blockedUsers` (`isBlocked`) и живой статус `banned` хотя бы в одном allowlist-чате (`residents.access(...).banned`). Второй нужен потому, что забаненного руками в Телеграме, минуя миниапп, в `blockedUsers` нет — а пускать его внутрь всё равно нельзя. Разблокировка (`unbanChatMember`) — **только dev** (API `unblock`, `requireDev`); список заблокированных с кнопкой «Разблокировать» лежит в дев-меню миниаппа (`bootstrap.blocked`, только dev-аккаунтам).
- Уведомления: новая заявка → DM резидентам по prefs (`hostingNotify`, дефолт «включено, только сегодня»); одобрение/снятие одобрения → DM гостю; отмена одобренного визита гостем → DM одобрившему. Рассылка — fire-and-forget (`void …catch`), чтобы не задерживать HTTP-ответ.
- Архив — недели с заявками (понедельник — ключ недели), включая **текущую**, только для резидентов и только чтение. Текущая неделя нужна потому, что обзор — скользящие 7 дней от сегодня, и уже прошедшие дни этой недели из него выпадают.
- **Календарь** — `GET /visit.ics?id=&initData=` (`buildVisitIcs`, RFC 5545). Путь намеренно вне `/api/` (там только POST): ссылку открывает системный браузер, поэтому `initData` едет в query, а не в теле; подпись и TTL проверяются те же. Отдаём **только свою** заявку (в файле цель визита и кто хостит). `DTSTART` — в UTC (пояс спейса → UTC), длительность фиксированная (`ICS_EVENT_HOURS`).
- Фронт (`webapp/src`, React + TypeScript) — стек экранов без роутера (внешний стор `store.ts` через `useSyncExternalStore`, императивные `push`/`pop`/`resetRoot`/`action`); пользовательские строки идут только через текстовые узлы JSX (никакого `dangerouslySetInnerHTML`), inline-SVG — только статические иконки (`icons.tsx`). Экраны — `src/screens/*`, переиспользуемые компоненты — `src/components/*`, модалки — `modals.tsx` (императивный `showAlert`/`confirmDialog`/`timePrompt` + портал). Нижняя панель и busy/модалки — через `createPortal` вне анимируемого `.screen`. **Свайп-действия** строки (`components/SwipeRow.tsx`) — жест влево открывает кнопки под строкой, как в нативных списках iOS: на строке заявки это «Заметка», «Перенести» и «Заблокировать» (инлайновых кнопок для них нет). Кнопки **иконочные и в трёх тонах** (`icon` + `tone` у `SwipeAction`: нейтральный `--gray`, синий, красный): три подписи растягивали панель почти на всю ширину строки, а два синих действия подряд читались как одно. Подпись остаётся в `aria-label`/`title`. Жест приходит **двумя путями, и оба обязательны**: Pointer Events (палец и зажатая мышь; направление решается по первым 8px, вертикаль отдаётся скроллу через `touch-action: pan-y`) и нативный `wheel` с `deltaX` — трекпад pointer-событий не шлёт вообще, без этой ветки на макбуке строка не двигается. Слушатель `wheel` вешается через `addEventListener({ passive: false })`, а не `onWheel`: React вешает колесо пассивно, а без `preventDefault` macOS уводит горизонтальный жест в навигацию «назад». Конец жеста трекпада ловится только паузой в событиях (`WHEEL_IDLE_MS`) — аналога `pointerup` у колеса нет, а инерция досылает события ещё долго после отрыва пальцев. Обратный жест (закрыть) работает так же обоими путями. Два неочевидных условия: `onDragStart` гасится вручную — в строке есть `<img>` аватарки, и перетаскивание с неё запускает нативный drag-and-drop, который тут же шлёт `pointercancel` и убивает жест мышью; панель действий держится `visibility: hidden`, пока строку не тронули, и открывается снова только по `onTransitionEnd` — перекрыть её сдвинутым контентом мало, слой с `transform` композитится отдельно и на дробном DPR давал полоску красного по правому краю. Открытая строка всегда одна на экран (модульная переменная `closeOpened`). «Принять {слот}» намеренно остался инлайн — ответ на живое предложение гостя за жестом прятать нельзя. Дев-меню (переключатель перспективы, сид фейковых заявок, правка/удаление любых заявок) видно юзерам из `DEV_USER_IDS`; сервер проверяет это сам, чип лишь прячет вход.
- **Тема** — `data-theme` на `<html>`, ставит JS; в CSS всегда приходит уже разрешённая (`light`/`dark`), выбор (`system`/`light`/`dark`) лежит в `localStorage`. Цвета иконок считает `sec(alpha)` в JS: в атрибут `stroke` инлайнового SVG CSS-переменную не подставить.

### Поток доски хостинга (`src/hosting-board.ts`)

Закреплённая доска «кто сегодня в спейсе» в каждом allowlist-чате. Стейт — `state.hostingBoard[chatId]` (`{ messageId, postedDay, shownDay }`). Включена только при заданном `WEBAPP_URL` (часть подсистемы хостинга).

- **Что показывает** — ближайший день с активностью в окне `[сегодня; +6]` (`activeDayForBoard`). Активность = есть подтверждённый визит, отметка резидента «я приду» **или** (только для сегодня) кто-то отмечен внутри спейса (`dayHasActivity`; pending-заявки сами доску не заводят). Если сегодня пусто, а завтра есть активность — доска показывает завтра; появилась активность на сегодня (в т.ч. чей-то чек-ин) — переключается на сегодня. Содержимое — блок «Сейчас в спейсе» (`insideBoardLines` из `presence.ts`, **только на доске сегодняшнего дня**) + публичный список `attendeesForDay` (тот же, что в bootstrap: резиденты «я приду» + подтверждённые неанонимные гости) + общее число заявок дня. «Сейчас в спейсе» = кто физически внутри (presence); «Придут» = кто планирует — это разные списки.
- **Одно сообщение в день, тихий пин** — `postedDay` = `todayKey` на момент отправки. Пока `postedDay === today`, доску только **редактируют** (`syncHostingBoard`). На смене дня (`postedDay !== today`) её **открепляют** и забывают; новая заведётся при первой активности нового дня. Пин — `pinMessage({ notify: false })` (без loud-уведомления); служебное сообщение «закрепил сообщение», которое возвращает `pinMessage`, тут же удаляем (`deleteMessages`), чтобы доска не тянула шум.
- **Что дёргает `syncHostingBoard`** — событийно из мутирующих ручек `webapp.ts` (`syncBoard()`: approve/attend/create/cancel/… — fire-and-forget), из presence через `setPresenceChangeHook` (чек-ин/чек-аут/MAC — ставится в `index.ts` только при включённом миниаппе) для мгновенной реакции, плюс `startHostingBoardScheduler` (тик 60 с) страхует переходы по времени (открепление на след. день, смена показанного дня) и держит счётчики свежими. Повторный edit тем же текстом ловит `MESSAGE_NOT_MODIFIED`; удалённое сообщение (`MESSAGE_ID_INVALID`/`MESSAGE_DELETE`) — забываем id и постим заново.
- **Кнопка «Хочу прийти»** — URL-кнопка на deep link миниаппа (`setHostingBoardLink`, тот же `t.me/<bot>?startapp=hosting`, что у списков присутствия). В группах web_app-кнопки запрещены, поэтому именно URL.
- **Мут** — `/boardmute` (админ чата, toggle, `state.hostingBoardMuted[chatId]`) отключает доску в чате: `syncChatBoard` в замьюченном чате открепляет и забывает висящую доску и новую не постит. Зеркалит `/goalsmute`/`/announcemute`.

### Поток анонсов (`src/announce.ts`)

- **Релиз** — воркфлоу `release.yml` триггерится пушем тега `vX.Y.Z`. Шаг «Ensure tag is on main» гейтит: `git merge-base --is-ancestor $GITHUB_SHA origin/main` — тег на dev игнорируется (релизим только доехавшее до main). Ченджлог собираем сами: `prev=$(git describe --tags --abbrev=0 "$TAG^")`, затем `git log --no-merges --reverse --pretty='- %s' "$prev..$TAG"` (нет прошлого тега → вся история до тега). Показываем ВСЕ коммиты, не только PR — GitHub-овский `--generate-notes` перечисляет лишь смёрдженные PR-ы, прямые коммиты игнорит. Версия = тег, `package.json` НЕ бампаем. Дисциплина тегов — ручная: не выпускать/двигать теги без нужды, иначе диапазон «с прошлого тега» посчитается криво.
- **Чтение** — `fetchLatestRelease(githubRepo)` бьёт в `releases/latest` анонимно (репо публичное). null — сети нет / релизов ещё нет (404).
- **Экран** — `announce.latest` (только dev) отдаёт последний релиз, `buildDefaultAnnouncement` (тело релиза → «Бот обновлён до версии X, ченджлоги: …» + ссылка `https://github.com/<GITHUB_REPO>` последней строкой — в чате сам ченджлог никуда не ведёт), `lastAnnouncedVersion`, число чатов-получателей. Фронт: textarea с дефолтом (правится), живое превью (`white-space: pre-wrap`), кнопка «Разослать в N чатов».
- **Рассылка** — `announce.send` (dev): `broadcastAnnouncement` шлёт `renderAnnouncement(text)` (построчный `html.escape` + `<br>` — иначе `\n` схлопнется) во все allowlist-чаты, кроме `announceMuted` (`/announcemute`, toggle, только админ чата). Ошибка отправки в чат логируется и не роняет остальные. `version` из тела запроса пишется в `lastAnnouncedVersion` (маркер, пусто для обычной рассылки). Метод работает с произвольным текстом — это база под универсальные рассылки.

### Поток бэкапов (`src/backup.ts`)

Дев-инструмент (`DEV_USER_IDS`), в меню команд не публикуется — как `/forcemacupdate`. Не-девам бот на эти команды **молчит**, чтобы они не светились; в группах работает только внутри `ALLOWED_CHATS` (личка дева — всегда).

- **`/backup`** — разово шлёт в текущий чат весь стейт файлом (`storage.snapshot()`, тот же JSON, что лежит на диске; имя — от `DATA_FILE` + метка времени UTC). Читаем in-memory снимок, а не файл: он всегда консистентен, в отличие от возможной гонки с `tmp+rename`.
- **`/autobackup <интервал>`** — расписание отправки в этот чат: `12h` / `3d` / `2w` / `1m`. **`m` — месяц, не минуты**; минут нет намеренно. `/autobackup` без аргументов — статус, `/autobackup off` — выключить. Включение шлёт первый бэкап сразу, дальше по интервалу.
- **Месяцы календарные** (`nextBackupAt`, UTC): `setUTCMonth(+N)` с зажимом в конец месяца (31 января + `1m` → 28/29 февраля). Через «30 дней» бэкап уползал бы по датам.
- **Стейт** — `state.backups[chatId]` (`{ chatId, value, unit, nextAt, lastSentAt, by }`), поэтому расписание переживает рестарт: пропущенный за простой бэкап уходит на первом тике. Шедулер (`startBackupScheduler`, тик 60 с) поднимается **всегда**, даже при пустом `DEV_USER_IDS` — иначе включённое расписание тихо перестало бы ходить. Битая `nextAt` считается «пора» (иначе запись зависла бы навсегда), ошибка отправки не двигает расписание на полный интервал, а откладывает на `RETRY_DELAY_MS` (15 мин).
- **Приватность** — в файле весь стейт: userId, ники, MAC-привязки, присутствие, заявки. Отправлять только в закрытый чат; команда об этом предупреждает при включении.

## Соглашения кода

- **TypeScript strict + `noUncheckedIndexedAccess`** — массивы/индексы возвращают `T | undefined`, всегда проверяйте или `!`-утверждайте после явной проверки длины.
- **ESM + NodeNext**: импорты в исходниках идут с расширением `.js` (`from './handlers.js'`), даже если файл `.ts` — это требование `module: "NodeNext"`. Не уберать.
- **Бэкенд — без билда**: запуск через `tsx` (`npm start` / `npm run dev`). `tsconfig.outDir = dist` есть, но не используется. **Миниапп — со сборкой**: Vite собирает `webapp/src` → `webapp/dist` (`npm --prefix webapp run build`), а `src/webapp.ts` раздаёт готовый `dist`. Перед `npm start` миниапп нужно собрать (или гонять `npm --prefix webapp run dev` с прокси на бэкенд). В Docker сборка миниаппа — отдельный шаг `Dockerfile`. У миниаппа свой `package.json`/`tsconfig.json` (React 18, strict TS, `noUncheckedIndexedAccess`).
- **Никаких сторонних логгеров** — `console.log/warn/error` достаточно. Префиксы `[warn]`, `[presence]`, `[scheduler]`, `[printer]`, `[keenetic]` — соблюдать.
- **Тексты пользователю — на русском**, тон соответствует существующим сообщениям.
- **`html()` схлопывает `\n` в пробел** — реальный перенос строки даёт только `<br>`. Многострочные сообщения собирать через `lines.join('<br>')` (см. `fundraiser.ts`), не `'\n'`.
- **Тип чата**: `msg.chat` — это `Peer = User | Chat`, дискриминатор `.type`. Личка с ботом — `msg.chat.type === 'user'` (НЕ `chatType`, он только у `Chat` и без значения `'private'`).
- **Картинка из байтов**: `msg.answerMedia(InputMedia.photo(uint8Array, { caption: html(text) }), { replyMarkup })`; подмена картинки в существующем сообщении — `ctx.editMessage({ media: InputMedia.photo(...) })`. На повторный edit той же картинки прилетает `MESSAGE_NOT_MODIFIED` — ловить и отвечать тихим `ctx.answer`.
- **Комментарии**: писать только когда «почему» неочевидно (см. существующие JSDoc-блоки над экспортами и встроенные комментарии о mtcute-нюансах). Не дублировать «что делает функция» — имена и сигнатуры самодокументируемы.

## Команды разработки

```bash
npm install
npm --prefix webapp install         # зависимости миниаппа (React + Vite)
npm --prefix webapp run build       # сборка миниаппа в webapp/dist (нужна перед npm start)
npm start          # tsx src/index.ts
npm run dev        # tsx watch
npm run typecheck  # tsc --noEmit  (бэкенд; это весь CI, тестов нет)

# Миниапп:
npm --prefix webapp run dev         # Vite dev-сервер :5173 с прокси /api,/avatar.jpg,/visit.ics на :8080
npm --prefix webapp run typecheck   # tsc --noEmit для webapp/src
```

`.env` обязателен: `API_ID`, `API_HASH`, `BOT_TOKEN`, `ALLOWED_CHATS` (через запятую), опционально `DATA_FILE` (по умолчанию `./data.json`), `PRINTER_URL` (Moonraker; без него `/printer` отключён), `KEENETIC_URL`/`KEENETIC_LOGIN`/`KEENETIC_PASSWORD` (все три — иначе авто-отметки по MAC отключены), `WEBAPP_URL` (+ `WEBAPP_HOST`/`WEBAPP_PORT`/`HOSTING_TZ_OFFSET_MINUTES`; без URL миниапп хостинга отключён), `GITHUB_REPO` (репо для чтения релизов в дев-анонсах, дефолт `endpoint-msk/robot`). Сессия mtcute — `bot.session` в CWD.

Тестов и линтера нет. После любых правок — `npm run typecheck`.

## Что НЕ делать

- Не кэшировать результат `getChatMember` в `state` — он намеренно живой.
- Не вводить миграции схемы стейта без необходимости: `Storage.load` устойчив к отсутствующим полям через `?? {}`.
- Не добавлять реакции/ответы в чатах вне `ALLOWED_CHATS`. «Молчание в чужих чатах» — это фича.
- Не путать `chatId` (Telegram, со знаком, с префиксом `-100` для супергрупп) и `channelId` (mtcute updates, без префикса). См. `registerPresenceDeleteWatcher`.
- Не писать новые таймеры через `setTimeout` chain — следовать паттерну `setInterval` + `tick` + `stop()`-handle, как в `scheduler.ts` и `presence.ts`.
- Не использовать `.then`/`.catch`-цепочки в новом коде; везде `async/await`.
