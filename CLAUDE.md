# CLAUDE.md

Гайд для LLM по проекту `endpoint-robot` - телеграм-бота хакерспейса на TypeScript + [mtcute](https://mtcute.dev).

## Документация mtcute

Индекс гайда и API-референса для LLM: <https://mtcute.dev/llms.txt> (первый источник для сигнатур и примеров). Полный референс: <https://ref.mtcute.dev>.

## Что делает бот

Девять подсистем с общим стейтом:

1. **Сборы донатов** (`fundraiser.ts`, `handlers.ts`, `scheduler.ts`) - один сбор на период, `/goals`, `/donate`, `/remove`, `/setgoal`, `/settitle`, `/history`. Лидерборд по нику (lower-case), топ-3 с медалями, `PAGE_SIZE = 10`. Цель, тема и описание «липкие»: новый период копирует настройки прошлого (`ensureCurrentFundraiser`), сбрасываются только донаты. Сообщение `/history` не попадает в `lastMessages`, иначе шедулер перерисовал бы его в текущий сбор.
2. **Присутствие резидентов** (`presence.ts`, `menu.ts`, `keenetic.ts`) - `/start`/`/menu` в личке (меню резидента, владелец команд `menu.ts`), чек-ин с ником или без. Пинг раз в 3 ч, без ответа 15 мин отметка снимается. «Кто внутри» показывает доска (`hosting-board.ts`) через `setPresenceChangeHook`; `/inside` постит разовый снимок, в личке только для `residents.isMember`. **Авто-отметка по MAC**: `/bindmac`, поллер Keenetic RCI ставит `source: 'mac'`, снимает через `MAC_ABSENCE_GRACE_MS` (10 мин). Онлайн-MAC держатся в памяти процесса (`isMacOnline`). Потолок mac-отметки `MAC_MAX_PRESENCE_MS` (14 ч), дальше обычный пинг. «Уйти» ставит подавление (`suppressedAt`), снимается уходом устройства из сети, не таймером. «Невидимка» (`presenceInvisible`) выключает авто-отметку. Роутер молчит дольше `MAC_STALE_MS` (30 мин) - все mac-отметки снимаются разом; ошибка роутера только в журнал (`/errors`), не чаще `MAC_REPORT_COOLDOWN_MS` (6 ч), кулдаун переживает восстановление.
3. **3D-принтер** (`printer.ts`) - `/printer` из Moonraker, **только резидентам и только в личке** (камера показывает помещение). Гейт и на каждом тапе callback-ов `printer:*`. Поллер 30 с шлёт подписчикам окончание печати.
4. **Хостинг гостей** (`hosting.ts`, `webapp.ts`, `webapp/`) - Telegram Mini App (включается `WEBAPP_URL`): гость оставляет заявку на один из ближайших 7 дней, резидент хостит. Перенос, передача хоста, блокировка, заметки о госте, замок дня, повестка, мягкая вместимость, отметки «кто пришёл», профиль гостя, `.ics`. Подробно - «Поток хостинга». `DEV_USER_IDS` - дев-меню (перспектива гость/резидент, `dev.seed`, `dev.update`/`dev.delete`, разблокировка).
5. **Ивенты** (`events.ts`, `event-intake.ts`) - заводит резидент в миниаппе, дата до года вперёд. DM резидентам, анонс в allowlist-чаты (`/eventmute`), пересылка поста из `ANNOUNCE_CHANNEL_ID` в личку бота даёт заготовку. Ответственные и форма-заявка с рецензентами.
6. **Анонсы версий** (`announce.ts`) - релиз из тега через `release.yml`, дев правит текст в миниаппе и рассылает во все чаты минус `/announcemute`. Ядро - бродкаст произвольного текста.
7. **Резидентские взносы** (`dues.ts`) - ежемесячный платёж, одна настройка на спейс. Только личка и миниапп, **в общий чат ничего**. Две стадии: `claimed` (резидент) → `paid` (dev). Зачтён только `paid`.
8. **Журнал присутствия** (`presence-log.ts`, `stats.ts`) - история визитов и статистика в миниаппе, раздел резидентский, отказ через `presenceNoLog`.
9. **Аккаунты резидентов** (`authentik.ts`, `outline.ts`, `resident-access.ts`) - вступил в `RESIDENTS_CHAT_ID`: аккаунт Authentik с логином-ником из Telegram в группе `AUTHENTIK_GROUP`. Вышел: аккаунт выключен, отключён в вики, группа снята, админка и тег в чатах сняты. Кабинет в своём профиле, у дева «Создать»/«Удалить» в карточке резидента. Подробно - «Поток аккаунтов».

### Ключевые инварианты

- **`onCallbackQuery`: на чужой callback `return PropagationAction.Continue`**, не голый `return` - иначе другие callback-хендлеры не увидят свой («кнопка ничего не делает»).
- **`State` плоский и однофайловый**, всё через `Storage.update(mutator)`. `storage.get()` отдаёт живую ссылку.
- **`periodKey` = `YYYY-MM` только при `resetDay = 1`**, иначе `YYYY-MM-DD` (`keyForPeriod`). «Прошлый сбор» ищет `previousFundraiser` по лексикографическому порядку ключей, не по формуле. Никогда не сравнивать ключи через локальное время.
- **`ALLOWED_CHATS` - единственный гейт «бот тут работает».** В чужих чатах бот молчит, даже на ошибки.
- **Кто резидент - только через `ResidentDirectory`** (`residents.ts`), не прямым `getChatMember`. Резидент = участник `RESIDENTS_CHAT_ID` (не бот), бот обязан быть там админом, иначе ростер пуст. Переменная не задана - откат на админов allowlist-чатов. Методы: `isResident`, `isMember`, `presenceChats`, `isChatAdmin`, `access` (резидент+участник+бан одним вызовом), `list`/`listIds`, `joinedAt`. **`list()` отдаёт `{ users, complete }`: по неполному списку вычёркивать нельзя.** Кэш в памяти (`MEMBER_TTL_MS` 60 с, `ROSTER_TTL_MS` 5 мин, дедуп, `invalidate`), кэшируются только ответы с RpcError-кодом, сетевой сбой - нет. В `state` кэш не класть.
- **`/inside` для всех участников allowlist-чата**, остальные команды сборов админские (два хелпера, два scope в `setMyCommands`). `/donate` не-админу отдаёт описание сбора из `/setdesc`.
- **Личка - не публичный API.** Команда, открытая в группе участникам, в личке проверяет человека сама (`/inside` → `isMember`, `/printer` → `isResident`, `/help` по роли). `requireUserInAllowedChat` в личке всегда ложь: забытая ветка лички = команда молчит.
- **GET вне `/api/` гейтятся сами** (`/visit.ics`, `/event.ics`, `/events.ics`, `/events-subscribe`, `/avatar.jpg`, `/event-photo.jpg`): `isBlocked` + видимость объекта. `/avatar.jpg` - только `disclosedUserIds` (иначе перебор id дёргает Telegram). **Регистрировать выше финального `serveStatic`**, он ловит любой путь.
- **Рейтлимиты - четыре слоя в памяти** (`ratelimit.ts`, полки `LIMITS`/`CLASS_LIMITS`/`METHOD_LIMITS` в `webapp.ts`): адрес, userId, класс метода (`read`/`write`/`dm`/`heavy`/`broadcast` по цене в Telegram), персональная полка. Считать по тому, сколько уйдёт в Telegram: клиент один, FLOOD_WAIT кладёт бота целиком. Полки списываются **до** `residents.access`. На отказе токены не списываются. Неудачные initData/токены - бакет `authFail` по адресу. Ответ `429` + `Retry-After`.
- **IP клиента из `CF-Connecting-IP`/XFF только от приватного пира** (`clientIp`): снаружи всё через туннель. Адрес - грубая сетка, настоящий учёт по userId.
- **Фейки дев-сида** (отрицательный `userId`, `isFakeUserId`) не выходят на публичные поверхности (доска, `attendeesForDay`, инлайн), в резидентских списках видны.
- **Стейт переживает битый файл**: `.corrupt-<время>`, подхват `.bak`, жалобы через `takeWarnings()` после `installErrorReporting`.
- **Стейт переживает откат кода**: `hydrate` = `{ ...parsed, ...известные поля }`, неизвестные ключи не стираются. Запись `open+fsync+rename`, коалесится.
- **Необработанное исключение = падение**: отчёт → `storage.drain()` → `exit(1)`. Порядок обязателен.
- **`telegram-web-app.js` - своя копия в `webapp/public`**, не с telegram.org (в РФ режут Telegram, вебвью идёт мимо прокси приложения). Обновляет воркфлоу `telegram-web-app.yml`, руками не править, `.gitattributes` держит без конвертации EOL. Подключён `defer`; `index.html` первой строкой ставит тему и шлёт `bootstrap`, `Root.tsx` забирает летящий ответ (`bootstrapOnStart`).
- **Статика**: `immutable` на год только файлам с хэшем в имени (`HASHED_ASSET`), `index.html` и `telegram-web-app.js` - `no-cache` + ETag. br/gzip в памяти, прогрев `warmStatic`. **Бандл на чанки не резать**: открытый до деплоя миниапп догружал бы чанк, которого нет.

### Поток сообщения сбора

`/goals`/`/donate` → `ensureCurrentFundraiser` → `renderFundraiser` → ответ + `rememberLastMessage`. Дальнейшие правки и `◀️▶️` → `refreshLastMessageInChat` редактирует запомненное; `MESSAGE_ID_INVALID`/`MESSAGE_DELETE` - забыть id. Строка «осталось N дней» считается в целых UTC-сутках, день сброса берётся из ключа сбора (`resetDayFromKey`), не из настройки. `renderFundraiser` принимает `now` последним параметром.

### Поток presence

Чек-ин `presence:checkin:nick|anon` → `checkInResident` → хук доски. Чек-аут `presence:checkout` → `removePresence` (единственная точка снятия, пишет журнал). Шедулер 60 с пингует только `source: 'manual'`. Без миниаппа хук не ставится, остаётся ручной `/inside`.

### Поток printer

`/printer` → `fetchPrinterStatus`; при печати превью gcode + кнопки `printer:view:preview|camera` (`ctx.editMessage({ media })`, повтор ловит `MESSAGE_NOT_MODIFIED`). `printer:notify` пишет в `printerSubscribers`; поллер на терминальном статусе шлёт и **чистит весь список** (подписка на текущую печать). Превью требует миниатюр в gcode; снимок - `snapshot_url` первой камеры, фолбэк `/webcam/?action=snapshot`.

### Поток хостинга

- **Аутентификация** - только подпись `initData` (HMAC `WebAppData`, TTL 24 ч), без сессий. Права на каждый запрос через `residents.access`.
- **`POST /api/bootstrap`** - 7 дней от сегодня, свои заявки, настройки. **Гостю в днях только счётчики**, детали - резидентам и девам. Мутации возвращают свежий bootstrap.
- **Кнопки бота ведут на место** (`deeplink.ts`): в личке query `to` у web_app-кнопки, из групп `startapp` у t.me-ссылки. Адрес только выбирает экран, права проверяет сервер, протухший адрес молча открывает главную. Символы - латиница, цифры, `_`, `-`. Стек ставится разом (`openAt`). Приоритет входа: `?draft=1`/`?onboarding=1`, адрес, затем знакомство.
- **Ключ дня `YYYY-MM-DD` по поясу спейса** (`HOSTING_TZ_OFFSET_MINUTES`, дефолт 180). «Сегодня» только через `todayKey(offset)`. Слот на сегодня не в прошлом (`isPastSlot`/`nowTimeKey`, bootstrap отдаёт `nowTime`).
- **Время - свой `TimeField`**, не `<input type="time">` (нативный рисует am/pm по локали). Колесо - скролл со `scroll-snap`, высота строго `5 × ITEM_H` (`--tp-item-h` = `ITEM_H`). Цифры - отдельный слой-барабан поверх прозрачного списка. В форме заявки колесо раскрывается в карточке (`TimeRow`), в узких местах - шторка.
- **Время по умолчанию** в форме гостя (`defaultTimeFor`): первый резидент, указавший время в этот день, плюс 30 минут (гости не в счёт: хост может прийти позже своего гостя; якорь позже 23:29 не берётся), иначе время прошлого подтверждённого визита гостя, иначе 15:00, сегодня ближайший час; прошедшее сегодня не предлагается. Смена дня меняет время, пока его не трогали, и перещёлкивает его (`Flip`), под колесом без движения (`still`). «Ко скольки?» резидента (`attendTimeFor`) открывается на времени первого, кто придёт, без запаса.
- **Правила заявок**: окно `[сегодня; +6]`, одна активная заявка гостя на день, отмена = удаление. Захостить может любой резидент, отменить одобрение - только одобривший.
- **Правка гостем** (`edit`) только у `pending`. Снимает висящее предложение переноса (DM автору); выставил ровно предложенный слот = согласие. Снимок предложения брать **до** `editHostingRequest` (живая ссылка).
- **Кто придёт** (`attendeesForDay`, видно всем): одобренные неанонимные гости + резиденты «я приду», резиденты первыми, дубли по `userId` схлопываются. Цель визита не публикуется. `anon` резиденты видят с меткой «инкогнито».
- **«Я приду»** (`hostingAttendance`, ключ `${dateKey}#${userId}`, API `attend`): время необязательное; строка ставит, `null` снимает, **отсутствие поля сохраняет** (кнопка «Приду» из зова времени не знает). Смена времени сохраняет `at` первой отметки и не шлёт повторный DM.
- **Подписка гостя на «я приду»** (`attend-alerts.ts`): рассылает шедулер, а не ручка; отметка должна простоять `SETTLE_MS` (5 мин). Каждая отметка объявляется один раз (`hostingAttendAnnounced` переживает снятие; метка ставится до отправки и без получателей). Закрытый день держит отметки до открытия. Получатели минус заблокированные, автор и резиденты; девы мимо фильтра.
- **Перенос** (`proposal` = `{ dateKey, time, by, to, user, at }`): полный слот, пинг-понг. День проверяется как при создании и **перепроверяется на accept** (`stale`). Встречное `propose` тем же слотом = accept; слот, равный согласованному или уже своему предложению, = no-op. На `pending` гость отвечает только на предложение резидента; на `approved` инициатива у обеих сторон, со стороны резидентов только хост. **`proposal.to` обязателен**: принять может только адресат, снять - адресат или автор (`proposalSides`), остальным 403. Записи без `to` - прежнее поведение. Уведомления называют автора действия; «снимает предложение» (автор) и «отклоняет перенос» (адресат) различаются.
- **Передача хостинга** (`request.transfer`): только одобренная заявка и только от хоста, адресат отвечает сам, одно предложение на заявку. Принятие переписывает `approvedBy` **и переносит переговоры переноса** на нового хоста (`proposal.to`/`proposal.user`). `unapprove` гасит передачу. Вход - тап по своему пиллу хоста; `transfer` уходит только в резидентские списки. Своё «Взять визит» не подменяет пилл: ник прежнего хоста перетекает в ваш буквами, «···» раскрывается последним (`useHandoff` в `RequestRow.tsx`).
- **Вместимость** (`SPACE_CAPACITY = 15`, `hostingDayCaps`): **мягкий** лимит, сервер ничего не запрещает. Занято = резиденты «я приду» + одобренные гости + принятые заявители ивентов, по головам; **ничьи заявки не входят** (показываются отдельно). Гостю вместимость не уходит.
- **«Позвать в спейс»** (`hosting-invite.ts`): кандидаты - резиденты + известные гости, зов - DM; закрытая личка → `409 dm_closed`. Незнакомых зовут карточкой через выбор чата (`share.prepare` с `kind: 'day'`). На закрытый день гостя звать нельзя.
- **Профиль открывается только по @нику**: `tg://user?id=` из вебвью не открывается ни одним способом, text-mention выкидывается приватностью. Не возвращать без нового механизма Telegram.
- **Правила спейса** (`HOSTING_RULES_VERSION`, `hostingRules`): лист поверх формы до первой заявки, **гейт продублирован на сервере** (`403 rules_required`). Текст во фронте, в стейте только версия; правишь текст - поднимай версию. Смахнули лист - форма уходит.
- **Заметка о госте** (`guestNotes`): одна на человека, общая, правит любой резидент; гостю не уходит никогда. Пустой текст = удалить. Блокировка заметку не стирает. В списке след заметки - только иконка.
- **«Я на месте»** (`arrivedAt`): окно `[слот − 30 мин; слот + 60 мин]`, кулдаун 5 мин, только своя одобренная. DM хосту, а если его нет внутри - всем внутри. **Гостю не сообщаем, кто внутри.**
- **Напоминание** (`request.remind`): опция, нет записи - молчим. **Момент отправки не хранится**, считается из слота; `sentAt` снимается при смене слота. Срок должен успевать и быть раньше визита (`reminderFits`), неподходящий в `create`/`edit` молча гасится в null. `sentAt` ставится и при неудачной отправке. Ответ на «Не смогу прийти» - сначала всплывашка, потом правка сообщения, потом доска (FLOOD_WAIT по имени метода на весь клиент). `remind` уходит только в свои заявки.
- **Свои прошлые визиты** (`myPast`, `myVisits`): гостю **без числа неявок** и без того, кто отметил. Свой визит на сегодня и завтра подписан «Сегодня» и «Завтра», как шапка дня (`visitDayWord`), дальше днём недели.
- **Значки визитов** (`guestVisitStats`, только резидентам): визит = `countsAsVisit` (приход по любому признаку **плюс «без отметки»**), неявка только явная, дни строго раньше сегодня.
- **Кто пришёл** (`visitOutcome`, `request.visit`, `hostingWalkIns`, `hostingVisitsSince`): отмечает любой резидент. Порядок доверия: явная отметка → `arrivedAt` → до `hostingVisitsSince` = приход → иначе «без отметки» (**не неявка**). `hostingVisitsSince` ставится один раз на старте. **Окно отметок - день визита и ночь до 06:00** (`isVisitDayEditable`), архив только чтение. «Не пришёл» - только у одобренной и не раньше слота. Ничьих заявок в отметках нет. Отмеченный и прошедший визит не удаляются (`409 visit_marked`/`past`). Смена слота снимает отметку. Гость без заявки по имени - `userId 0`; с заявкой на этот день - отмечается по ней (`has_request`). Walk-in не идёт ни в «кто придёт», ни на доску.
- **Закрытие заявки резидентом** (`close`): ничью - любой, одобренную - только хост. Комментарий до 500 символов уходит цитатой, в журнал - только факт. DM здесь ждут (`delivered` true/false/null).
- **Закрытый день** (`hostingDayLocks`): закрывает любой резидент, запрет только на **гостевые** заявки (`400 day_locked`), резиденты отмечаются. Причина видна гостю, автор - нет. **Закрытый день не выходит на доску**, но уже висящая доска при `activeDay === null` откатывается на сегодня, поэтому у `buildBoardMessage` для закрытого дня свой текст, а кнопка гасится **пустой разметкой, не `undefined`**. Поданные заявки не трогаются. Гейт - на **переезде** в закрытый день (`movesIntoLockedDay`), сдвиг времени внутри дня разрешён.
- **Повестка дня** (`hostingDayAgenda`): одна на день, общая, текст видят все, автора - только резиденты. Делает день «непустым» в строке, но **доску не заводит**. В журнал пишется текст и прошлый автор. В интерфейсе и текстах ошибок она «Тема дня», а исход визита в отметках - «визит», не «приход». На экране дня тема - **строкой шапки под датой** (`DayTopic`, у гостя тоже), отдельной плашки нет; автор - подписью строки «Тема дня» в карточке «День», текст там не повторяется.
- **Блокировка**: любой резидент блокирует гостя; **резидента нельзя** (400). Бан во всех `ALLOWED_CHATS`, стирание заявок/отметок/присутствия, `403 blocked` на `/api/*` и `.ics`. Источников два: `blockedUsers` и живой `banned` из `residents.access`. Разблокировка - только dev.
- **Уведомления** fire-and-forget (`void …catch`). Новая заявка → резидентам по `hostingNotify` (дефолт «только сегодня»).
- **Архив** - недели с заявками или walk-in, включая текущую, только резидентам; день открывается «Кто пришёл» на чтение.
- **`.ics`**: `GET /visit.ics?id=&t=` и `/event.ics`, **не initData** (URL оседает в истории), а токен ссылки `signLink`/`verifyLink` на 15 мин под объект; фронт берёт его заранее (`useIcsLink`), т.к. `openLink` после `await` может не считаться ответом на тап. Картинки - `mediaToken` с окном 6 ч. Только своя заявка. `DTSTART` в UTC.
- **Фронт**: стек экранов без роутера (`store.ts`: `push`/`pop`/`resetRoot`/`action`/`setTopParams`/`replaceTop`). Пользовательские строки только текстовыми узлами JSX, без `dangerouslySetInnerHTML`. Нижняя панель, модалки и оверлеи - через `createPortal` вне анимируемого `.screen`. `BackRow` только вне Telegram и в клиентах старше 6.1.
- **Найденное подсвечено** (`Found` в `components/common.tsx`) в поисках архива, «Позвать», гостя без заявки и ответственных: первое вхождение, тем же сравнением, что у фильтра. Архив ищет на сервере (отбрасывает «@», находит и по номеру аккаунта), поэтому строка может прийти без подсветки.
- **Поиск один** (`SearchField` в `components/common.tsx`): серое поле iOS с лупой и крестиком на всех поисках. Фильтры сравнивают через `searchNeedle` (без регистра и «@» в начале) и его же отдают в `Found`. Само поле значение не правит: «Без заявки» по сырому «@нику» ищет человека в Telegram.
- **Одна линия слева**: отступ содержимого карточки `--row-x` (16 px) у строк, заголовков секций и карточек. Разделитель - `<Sep inset="text" | "icon" | "avatar" />` или ширина своего ведущего элемента числом (плитка дня 72, отметка взноса 22), не готовым отступом: при смене отступа литералы разъехались бы с текстом.
- **Строки с элементом управления 52 px**, как строка с иконкой: тумблер, меню, время, «−»/«+». Строка с тумблером - `SwitchRow`, переключатель на всю строку (тумблер внутри нарисован, кнопкой не является). Карточка, где такие строки соседствуют с текстовыми, - `card ctl-card`: текстовые в ней тоже 52.
- **Капсула статуса одна** (`.visit-chip`, `.rate-chip`, `.debt-badge`, `.resident-badge`, `.ob-tag`, `.ev-chip`): 20 px, 12/600, строчными, смысл несёт цвет. Текст зелёным и оранжевым - `--ok-fg` и `--warn-fg`; `--green` и `--orange` только заливкам и иконкам (на белом 2,2:1).
- **Выключенный поток уведомлений** - `NotifyIcon` (`components/common.tsx`): серая плитка и перечёркнутый колокольчик, в настройках резидента и гостя («Придут резиденты») и в шаге «Что присылать» знакомства. Значок строки с выбором потока - только он. В строке с тумблером он идёт за ползунком (`icon` у `SwitchRow` функцией от положения), а не за ответом сервера.
- **Кнопки капсулой** (`--radius-btn: 999px`), как пиллы и как в iOS 26. Плитки гостя («Как пройти», «Активность») - `--radius-tile` (16): капсулой они читались бы кнопками действия.
- **Под нижней кнопкой край, а не плашка** (`.bottom-bar::before`): экран продолжается размытым и гаснет кверху маской, подкраска готовым `--bg-edge`. На `.low-motion` прежняя плашка в цвет фона: размытие перерисовывается на каждом кадре прокрутки.
- **Листы парят** (`.modal-sheet`, `.tp-sheet`, `.resp-sheet`, `.ob-sheet`): в 8 px от краёв и над домашней полоской (`--sheet-gap`), радиус `--radius-sheet` (38 = кнопка в листе 22 + поле 16). Высокий (выше 80% окна) и с полем в фокусе прилипают к краям классом `attached` (ставит `useSheetDrag`). Спрятанный лист уезжает дальше на свой нижний отступ: `hiddenAt` в modals.tsx и `reach` в useSheetDrag считают его по `margin-bottom`, не по низу окна (на iOS обёртку листа поднимает клавиатура).
- **Desktop шире колонки**: в окне шире 520 px горизонтальная обрезка на `body`, а не на `#app`, и полосы дня и ивента идут до краёв окна (`calc(50% - 50vw)`). Внутри `.card` обводка фокуса рисуется внутрь строки: карточка режет всё за своим краем.
- **Клавиатура Desktop** (`Root.tsx`): Escape (лист, поле, назад), «/» ставит курсор в поиск экрана, Ctrl/⌘+Z вне поля - «Вернуть» с плашки, Ctrl/⌘+Enter из поля отправляет только то, что ничего не рассылает: лист вопроса без красной кнопки (`data-confirm`) и форму заявки (`ActionButton submit`). **Публикацию ивента, анонс и красные листы этой клавишей не подключать.** Клавиши по `code`, не по букве (русская раскладка).
- **Поля ввода растут** через `growField` (`motion.ts`): за набором высота едет 120 мс, текст из кода встаёт сразу (`still`), многострочный лист вопроса до шести строк.
- **Свой профиль** в настройках - `PersonPage` из `StatsPerson.tsx` с `profile` (имя и ник в шапке), права дева идут `extra` под ней. Чужой профиль у дева прежний.
- **Афиша в строке ивента** (`EventRow`, не плитка «Позже»): фото тем же адресом, что на экране ивента (`private, max-age=3600`, экран открывается уже с ним), без фото и при битом фото рисованная миниатюра.
- **Свайп-действия** (`SwipeRow.tsx`): иконки в четырёх тонах, подпись в `aria-label`. Жест двумя путями, оба обязательны: Pointer Events и `wheel` с `deltaX` (трекпад pointer-событий не шлёт), `wheel` через `addEventListener({ passive: false })`, не `onWheel`. `onDragStart` гасится (иначе `<img>` рвёт жест `pointercancel`). Панель действий `visibility: hidden`, пока строка в покое (иначе полоска на дробном DPR). Открыта одна строка на экран. «Принять {слот}» остаётся инлайн.
- **`Swap`** (загрузка → данные): каркас после `SKELETON_DELAY_MS` (320 мс), гаснущий слой в `useLayoutEffect`, `fadeOnly` в `Root.tsx` (transform ломает `position: fixed`).
- **Тема** - `data-theme` на `<html>`; цвета иконок через `sec(alpha)` в JS (CSS-переменную в `stroke` не подставить). Акцент из `themeParams.button_color` приводится к нашим фонам (`applyAccent`); зелёный/оранжевый/красный и графики остаются нашими.

### Движение и отклик во фронте

- **Движение только в ответ на свой тап** (`markOwnTap`/`ownTapRecent`, окно 5 с). Чужое изменение - без движения. Обучающих автоанимаций нет: каждый заход в миниапп - новая сессия.
- **Эталон - морф «Захостить» в пилл хоста**: `E.crisp`, 0,2-0,34 с, размытие+прозрачность+масштаб 0,88-0,9, без перелётов. Пружины рабочих экранов `damping: 1`. Отскоки только в знакомстве и итогах месяца.
- **`motion.ts`** - общий язык: `E`, `animate`, `spring`/`rubber`/`project`/`tracker`, `pageTarget`, `holdSelection`, `reducedMotion()` (учитывает слабый Android, класс `.low-motion`).
- **Доводки кадрами системы** (`play`, `springPlay` в motion.ts): на iPhone с 120 Гц вебвью Telegram рисует кадры `requestAnimationFrame` на 60, а Web Animations по transform и opacity на 120. Так идут доводка свайпа назад, подъём и уход листа, плашка «Вернуть» и `Flip`. Правила: в кадрах только transform и opacity (с другим свойством WebKit ведёт анимацию сам, на 60); конечный вид инлайном до старта, без `fill`; остановка ставит инлайном вид текущего момента и только потом снимает анимацию (она перекрывает инлайн, и жест поверх неё был бы не виден). Листалки (в том же кадре полоса, высота, точки, подхват на лету по точной позиции), жест «вниз» (`clip-path`) и `SwipeRow` (сдвиг в состоянии React) остаются на кадрах JS.
- **Экран по касанию въезжает целиком** (`pageSwap` в hero.ts, `push`/`pop` в app.css): View Transitions с геометрией свайпа назад (прежний на −30%, яркость 0,8, тень у края), 0,36 с, «назад» обратным ходом; с главной кнопкой гостя (`slide`) экраны едут так же, кнопка стоит. В окне шире 520 px, без View Transitions (iOS 17 и старше) и при уменьшенном движении прежнее проявление со сдвигом 32 px. Шапку Telegram экраны красят в конце перехода (`afterHero`). На время перехода у html нет касаний, свайп назад не берётся; переход, не закончившийся за 1,5 с, доводится сразу. Playwright WebKit для Windows падает на части переходов (в статистику; назад с визита - и на 67ac6fb): iOS это не предсказывает, переходы проверять на iPhone.
- **Отклик** (`haptic`): `tick` - смена значения под пальцем, `impact` - свой тап, `notify` - только невиданный исход. `Switch` и destructive-кнопки диалогов бьют сами.
- **Тихий ответ**: `action(..., { quiet: true })` + `ActionButton` там, где меняется одна строка; оверлей у переходов и долгих операций.
- **Листалки** (`DayPager`, `Pager`): всё от дробной позиции правками `style`, цель отпускания от текущего места (`pageTarget`), смена дня - `setTopParams`, а не новый экран. Не брать касания в `.swipe-row`, полях ввода, `[data-scrub]` и **левых 30 px** (`EDGE_ZONE`, их забирает Telegram iOS).
- **Назад свайпом** (`useSwipeBack.ts` на `Screen`) и **жест «вниз»** (`usePullDismiss.ts`): прежний экран картинкой через `setUnder`, уход `popStill`. Листалки отдают свайп назад только с первой страницы (`registerPagerStart`).
- **Удалённое рассыпается** (`dust.ts`) после своего тапа; **строка уходит из данных только после свёртки** (`removeRow`), отказ сервера собирает её обратно.
- **«Вернуть» вместо подтверждения** (`undo.ts`): шесть обратимых действий. Сервер применяет сразу, DM людям держит до конца отсчёта +1,5 с и перепроверяет актуальность. `409 undo_stale`, `410 undo_gone`. Подтверждение осталось у необратимого и того, где есть ввод.
- **Ожидание сети** (`net.ts`): только ручки из `RETRY_SAFE`, повторы по очереди.
- **Вопросы - один лист снизу** (`modals.tsx`, `ModalSheet`). Под листом `#app` уменьшается transform'ом, поэтому **новый `position: fixed` внутри `#app` должен учитывать `--sheet-vb`/`--sheet-vt`**. Склонять имя гостя в тексте нельзя - человек ставится в шапку (`subject`).
- **Стекло** - готовые `--bg-glass` и `--bg-edge` (без `color-mix` для iOS < 16.2): плашка месяца над списком, прилипший переключатель статистики и край под нижней кнопкой. На карточках и в меню стекла нет: полупрозрачное меню отклонено.
- **Не возвращать** (пользователь отклонил явно): переход «строка вырастает в экран»; строку с названием экрана на всех экранах, в том числе строку с именем на стекле в профиле; кнопку «Визиты» в шапке профиля; автопоказ свайпа и сноски-подсказки; желе, растяжки, перелёты, сборку графика по кускам; растяжку шапки при жесте «вниз»; подсветку скопированного текста; плашку итогов на главной и карту месяца для историй; перелёт лупы к строке; ряд мест по одному во вместимости; точки перед статусом.

### Поток доски хостинга (`src/hosting-board.ts`)

Закреплённая доска в каждом allowlist-чате, стейт `hostingBoard[chatId]` = `{ messageId, postedDay, shownDay }`, только с `WEBAPP_URL`.

- Показывает ближайший день с активностью в `[сегодня; +6]` (`activeDayForBoard`): одобренный визит, «я приду», открытый ивент или (только сегодня) кто-то внутри. Закрытый день активным не считается. `residentsOnly`-ивенты не выносятся. «Сейчас в спейсе» (presence) - только на доске сегодня, «Придут» - `attendeesForDay`.
- Одно сообщение в день, тихий пин (`notify: false`), служебку о пине удаляем. На смене дня открепляем и забываем.
- `syncHostingBoard` дёргают ручки миниаппа, хук presence и шедулер 60 с. `MESSAGE_NOT_MODIFIED` ловить, удалённое - забыть id и постить заново.
- Кнопка «Хочу прийти» - URL `t.me/<bot>?startapp=new-<день>` (web_app-кнопки в группах запрещены).
- `/boardmute` (админ чата) открепляет и выключает доску в чате.

### Поток инлайна (`src/inline.ts`)

Требует `/setinline` в BotFather. Выдача: доска (`buildBoardMessage`) и ничьи заявки `[сегодня; +6]`. **Гейт - резидентство**, allowlist тут не работает; не резиденту пустая выдача со `switchPm`. **`private: true` и `cacheTime: 0` обязательны** (иначе Telegram отдаст выдачу резидента другому). `anon` в отправленном сообщении - «инкогнито», фейки выкинуты. Цель визита в сообщении есть намеренно.

### Поток анонсов (`src/announce.ts`)

### Поток ивентов (`src/events.ts`, `src/event-intake.ts`)

- **Афиши не в JSON**: файлы в `event-photos/`, в стейте `hasPhoto`. `/event-photo.jpg`: резидентский ивент гостю не отдаём, заготовку - только владельцу.
- Правка и удаление - автор или dev (`canEditEvent`).
- **Анонс в чаты** только при создании, без `residentsOnly`, организатор t.me-ссылкой (не text-mention), подпись до 1024 символов. `/eventmute`.
- **«Переслать»** (`share.prepare`, `prepareInlineMessage`): карточку просим на `pointerdown`. Афиша заливается раз (`sharedPhotoIds` в памяти). `residentsOnly` и прошедший не пересылаются.
- **DM резидентам** (`eventNotify`, дефолт «на любой день»): создание, перенос (старый слот снимать **до** `updateEvent`), отмена (снимок до удаления) - одним тумблером.
- **Заготовка из канала**: пересылка от `ANNOUNCE_CHANNEL_ID` → `eventDrafts[userId]`, кнопка на `?draft=1`. Форматирование теряется намеренно. При создании афиша переезжает (`adoptDraftPhoto`), заготовка снимается.
- **Черновик нового ивента** (`drafts.ts`): `CloudStorage` (куски по 4096), без афиш, **только у создания** - не делать черновики общих полей и правки.
- **Календарная подписка** (`/events.ics`, `eventFeedTokens`): https-ссылка `/events-subscribe` отвечает 302 на `webcal://` (из вебвью `webcal:` не открыть), хост из `Host` через whitelist символов. Гейт - личный токен (живёт месяцами). **В фиде только то, что видно и без него**: будущие ивенты без `residentsOnly` и свои одобренные визиты без цели. Токен искать перебором с `secretEquals` (не `tokens[key]` - `__proto__`). Живой бан не проверяем, хватает `blockedUsers`.
- **Тон афиши** (`tone`, `#rrggbb`): считает миниапп (`compressImage`), сервер принимает только валидный и только если первая афиша доехала. Цвета экрана - `toneColors`; `EventRow`/`EventCard` в `memo` не оборачивать (тема).
- **Ответственные** (`responsibles`): информационно, прав не дают, только резидентам, имена резолвит сервер, выпавший из пула не теряется (`keep`).
- **Форма-заявка** (`form`, `eventApplications`): поля `text`/`choice`, `required` проверяется на сервере, ответы - снимок текста. Рецензенты `all`/`creator`/`circle`; автор и dev - всегда. Отмена гостем и отклонение = удаление. Принятые идут в «кто придёт» и в занятость дня. «Принять» отвечает на тапе: подпись перетекает в «Принят» на месте, как «Захостить», а карточка **стоит в «На рассмотрении» до ухода с экрана** (`held` в `EventApps.tsx`), в «Приняты» она переезжает на следующем заходе.
- **Вопросы формы переставляются за ручку** (`components/useListReorder.ts`), сразу, без удержания (у ручки `touch-action: none`, иначе палец прокручивал бы страницу). Цель считается по переднему краю, а не по середине: вопросы разной высоты, и высокий выбор иначе не встал бы над коротким соседом. С клавиатуры - стрелки на ручке. Ленту афиш ведёт другой хук (`useReorder`): там шаг общий и палец берёт только удержанием.

### Поток взносов (`src/dues.ts`)

- `state.dues` одна на спейс. **В чат не пишет ничего.**
- **Ключ периода** `YYYY-MM` только при сборе 1-го, иначе `YYYY-MM-DD`. Открытие - день из **ключа** в 12:00 по поясу (`duesAnchorOf`). Тик сравнивает «есть ли период за текущий расчётный месяц», а не «сегодня день сбора». Подпись - по месяцу, который период покрывает (`displayMonthOf`).
- **Нулевая ставка = освобождён**: без DM, вне счётчиков и просрочки, не обрывает чужой счёт.
- **Ростер - снимок**, сверка раз в час (`ROSTER_SYNC_INTERVAL_MS`) только активного периода; вычёркивать только по `complete`; **пустой ростер откатывает период**.
- Недоставленный DM - `notifyFailed`, повтор раз в час сутки.
- `claimDues` → `confirmDues` (dev) → `clearDuesMark` (dev). `isPaid` - единственный признак.
- Ставки `rates[userId]`: нет записи - общая, `'student'`, число.
- Напоминания `REMIND_STAGES` (10 дней и сутки до следующего периода), метка `reminded` ставится и при недоставке.
- Читают резиденты, меняет dev; `dues.claim` и `dues.notify` - свои. Выгрузка - файлом в личку.

### Поток журнала присутствия (`src/presence-log.ts`, `src/stats.ts`)

- Пишутся **закрытые интервалы**, единственная точка - `removePresence`. Сырые сессии в `presence-log/YYYY-MM.ndjson` (append-only, не обрезаются), в стейте только дневные итоги.
- **`endReason` обязателен**: mac → `lastSeenOnlineAt`, таймаут → `lastConfirmedAt` (не меньше `TIMEOUT_MIN_SESSION_MS`), `stale` - роутер замолчал.
- Склейка на чтении (`GLUE_GAP_MS` 15 мин). День пересчитывается целиком (`recomputeDay`). `openMinutes` ≠ `manMinutes`.
- **Провалы роутера** (`day.gaps`): отсчёт от `lastSuccessAt + MAC_STALE_MS`, ячейка списывается от `GAP_MIN_MINUTES` и **только если в ней пусто** - фильтр на чтении, общий для тепловой карты и дня. Без привязок `lastSuccessAt` держится свежим.
- Сегодня считается на лету (`openSessionsNow`), из тепловой карты исключено.
- **«История по дням»**: `stats.days` отдаёт `buckets` и `gaps` дня (у сегодня провалы из стейта), строка рисует сутки двенадцатью ячейками в ступенях карты, верх шкалы общий (`DAY_CELL_FULL`, 240 человекоминут). «С … до …» ушло в `aria-label` ячеек; у дня без `buckets` подпись прежняя. «Последние визиты» в профиле - та же полоса (`VisitStrip` в `StatsPerson.tsx`), но тон по минутам самого визита в двухчасовой ячейке; визит через полночь доходит до 24:00.
- Все `stats.*` под `requireResident`, ручки зовут `discloseUser` для аватарок. **Режим «без ника» на журнал не распространяется** (`realUsername`).
- **«Резидент с»** - три источника раздельно: ручная дата (dev, `residentSince`, маркер `'origin'`), `joinedAt` из Telegram (не копить в стейте), первый визит.

### Поток итогов месяца (`src/wrap.ts`, `webapp/src/screens/Wrap.tsx`)

Прошлый календарный месяц, только свои числа и одно имя «с кем чаще», без рейтингов. `presenceNoLog` исключает и из своих, и из чужих. Меньше `WRAP_MIN_EVENINGS` (3) вечеров - итогов нет. Вечер - день начала визита, часы - из дневных итогов. Кэш в памяти (TTL 10 мин), в `State` не класть.

### Поток бэкапов (`src/backup.ts`)

Дев-команды, не-девам молчание, **только личка дева**; адресат расписания сверяется с `DEV_USER_IDS` на каждом тике. `/backup` - `.tar.gz` (свой ustar) из `storage.snapshot()` + `presence-log/`, `event-photos/`, `audit/`, `errors/`, тихо. `/autobackup 12h|3d|2w|1m|off` (**`m` - месяц**, календарный с зажимом). Шедулер поднимается всегда; битая `nextAt` = пора; ошибка - повтор через 15 мин.

### Поток знакомства (`src/onboarding.ts`, `webapp/src/screens/Onboarding.tsx`)

- Приглашение в личку на вступлении в `RESIDENTS_CHAT_ID` и на первом `/start` (один раз, `invitedAt`); на вступлении сброс кэша директории.
- `residentOnboarding[userId]`, `onboardingSince`. Первое включение отмечает всех текущих резидентов прошедшими - **только по полному списку**, иначе повтор раз в 10 мин; до этого знакомство не показывается никому.
- «Прошёл» пишется на «Готово». Поднятая `ONBOARDING_VERSION` показывает заново.
- В сотах «в спейсе» только отметившиеся с ником. Шаги зависят от данных (взносы, принтер).

### Поток аккаунтов (`src/resident-access.ts`, `src/authentik.ts`)

- **Ключ - атрибут `telegram_id`, а не логин.** Логин - ник из Telegram строчными (без ника `tg<id>`), почта - `<логин>@AUTHENTIK_EMAIL_DOMAIN` (Outline без email не пускает). Ник человек меняет, и освободившийся занимает другой, поэтому искать и связывать по нему нельзя. Привязать аккаунт ко входу через Telegram API не умеет (`user` у связи с источником только для чтения, goauthentik/authentik#25673), а `sub` из id_token Telegram не равен id. Связывает сам Authentik: у Telegram-источника режим username_link и маппинг, который находит аккаунт по `telegram_id` из id_token (`ak_user_by`) и подставляет его логин. Не нашёл - `None`, вход отклоняется: через Telegram регистрируются только аккаунты от бота. Маппинг в `.env.example`.
- **Атрибут бывает строкой и числом** (руками в YAML его пишут без кавычек): `findByTelegramId` и маппинг пробуют оба. Ответ фильтра по атрибутам сверяется на месте: на ошибке разбора Authentik отдаёт всех.
- **Логин занят** (без учёта регистра) - `taken`, второй аккаунт не заводится: обычно это старый аккаунт того же человека. Его отдают боту, вписав атрибут `telegram_id` (id в карточке у дева), не переименовывая. Вписывать только убедившись, что аккаунт его: иначе человек войдёт в чужой.
- **Выход** (`left`/`kicked`/`demoted_kicked`): `is_active: false` - Authentik в этом же вызове удаляет сессии и стирает OAuth-токены. Затем `users.suspend` в Outline по почте аккаунта: сам Outline сверяет токен только на загрузке и только через час после входа, открытая вкладка жила бы дальше. Возвращение (`grantAccess` по найденному аккаунту) снимает отключение. Группа снимается последней и только если вики отключилась: участник группы вне чата резидентов - метка «снято не всё» для сверки. Админка и тег - только выданное ботом (`canEdit`), владельца не трогаем. Сбой - `[access]`, он из `CRITICAL_PREFIXES`.
- **Хендлер в группе диспетчера 1**: знакомство в группе 0 вступление дальше не пропускает.
- **Сверка раз в час** (`startAccessReconciler`): только участники группы с `telegram_id`, только по полному составу меньше 200 и после одиночного `isResident` (состав кэшируется на 5 минут). Права в чатах не сверяет. Сама аккаунты не заводит. Лежащий Authentik - повтор на следующем тике без ошибки пульса, иначе он ронял бы `/healthz`.
- **`account.create` не резиденту - 409.** Вернуть доступ - «Включить», а не удалить и создать: у нового аккаунта новый `sub`, а неподтверждённую почту (`email_verified: False` у стандартного маппинга) Outline к прежнему аккаунту вики не привяжет.
- Кабинет - `${AUTHENTIK_URL}/if/user/` в `bootstrap.accountUrl`, только резидентам, без похода в Authentik.

### Код домофона (`src/door.ts`)

Код в стейте (репо публичный), правит dev, в журнал только факт. Наружу только резидентам и dev: `bootstrap.door` и кнопка в `/menu` (всплывающим окном, не сообщением). На главной миниаппа - под пеленой-спойлером, под которой болванка, а не код; сама закрывается через минуту.

### Поток журнала действий (`src/audit.ts`)

- Нужен, потому что отменяющие действия стирают поле, где лежал бы актор (`unapprove`, `close`, `cancel`, `decline`, `dues.clear`).
- Одна точка перехвата - обёртка вокруг `handleApi` в `webapp.ts`, плюс кнопка «Не смогу прийти», `dues:claim`, кнопки передачи хостинга и мьюты чатов.
- Только мутации из `AUDITED`. **Снимок объекта до `handleApi`** (`auditBefore`). Строка человекочитаемая (`describeAudit`), id в `meta`. Отказы пишутся тоже (код из `lastApiError`), логирование в `finally`.
- Запись не ждут (цепочка промисов), `drainAudit()` на выключении и в `onFatal`.
- **Содержимое не пишется** (цели визита, заметки, реквизиты); исключения - публичные тексты (анонс, причина закрытия, повестка), обрезанные.

## Соглашения кода

- **TS strict + `noUncheckedIndexedAccess`**.
- **ESM + NodeNext**: импорты с `.js` даже для `.ts`.
- **Бэкенд без билда** (`tsx`). **Миниапп со сборкой** (Vite → `webapp/dist`), свой `package.json`/`tsconfig.json`, тайпчек фронта отдельным шагом CI.
- Только `console.*`, префиксы `[warn]`, `[presence]`, `[scheduler]`, `[printer]`, `[keenetic]`.
- Тексты пользователю на русском, в тон существующим.
- **Число и слово не разрываются**: неразрывный пробел («5 заявок», «к 18:30»), разряды сумм узким. Хелперы `dates.ts`/`format.ts` делают это сами; строку, собранную из частей, оборачивать в `nb()` из `format.ts`.
- **`html()` схлопывает `\n`** - переносы только `<br>` (`lines.join('<br>')`).
- Личка с ботом - `msg.chat.type === 'user'` (не `chatType`).
- Картинка: `msg.answerMedia(InputMedia.photo(bytes, { caption }), { replyMarkup })`, подмена - `ctx.editMessage({ media })`, повтор ловит `MESSAGE_NOT_MODIFIED`.
- Комментарии только про неочевидное «почему».

## Что НЕ делать

- Не кэшировать `getChatMember` в `state`.
- Не вводить миграции схемы без необходимости: `Storage.load` терпит отсутствующие поля.
- Не отвечать в чатах вне `ALLOWED_CHATS`.
- Не путать `chatId` (с `-100`) и `channelId` (без префикса), см. `event-intake.ts`.
- Не писать таймеры цепочкой `setTimeout`: `setInterval` + `tick` + `stop()`. Исключение - одноразовые таймеры «Вернуть» в `src/undo.ts`.
- Не использовать `.then`/`.catch`-цепочки в новом коде.
